## 1. Executive Summary

### هل يوجد نظام شهادات فعلي أم مجرد واجهات؟
**يوجد نظام شهادات فعلي ويعمل.** ليس مجرد واجهات. يتكون من:
- قالب PDF موحّد فاخر (v2 "Prestige Edition") يُستخدم لـ 3 أنظمة شهادات ديناميكية.
- نظام تحقق موحّد يفحص 4 مصادر بيانات مختلفة.
- QR code حقيقي على كل شهادة PDF.
- صفحة تحقق عامة تعمل بالفعل.
- لوحة أدمن لإصدار شهادات يدويًا لأي بوابة.

### كم شهادة أو قالب شهادة موجود في المشروع؟
| # | النوع | الحالة |
|---|-------|--------|
| 1 | قالب PDF موحّد (`CertificateTemplate.tsx`) | جاهز |
| 2 | شهادة تقييم اللغة (Language Assessment) | جاهزة |
| 3 | شهادة الاختبارات الرقمية (Digital Exams) | جاهزة |
| 4 | شهادة إتمام الدورة (AI Academy / Courses) | جاهزة |
| 5 | شهادة يدوية من الأدمن (Admin-Issued) | جاهزة |
| 6 | معاينة قالب لكل بوابة (6 بوابات) | جاهزة |

**المجموع: 6 أنواع شهادات / قوالب فعلية.**

### في كم بوابة تظهر الشهادات أو تُستخدم؟
الشهادات تظهر أو تُستخدم في **6 بوابات**:
1. Language Portal
2. Digital Transformation Exams
3. AI Academy (عبر Course Completion)
4. Automation Academy (admin-issued فقط)
5. Career Hub (admin-issued فقط)
6. IoT Lab (admin-issued فقط)

### هل الشهادات مركزية أم متفرقة؟
**مركزية في التصميم، متفرقة في البيانات.**
- التصميم: قالب واحد موحّد (`CertificateTemplate.tsx`) يخدم كل البوابات.
- البيانات: 4 جداول منفصلة (`language_results`, `digital_exam_results`, `certificates`, `admin_certificates`).

### هل يوجد QR verification فعلي؟
**نعم.** كل شهادة PDF تحتوي على QR code يشير إلى:
`https://darhous-ai-cloud-academy.vercel.app/[locale]/certificates/verify/[certId]`

### هل يوجد PDF / download / print فعلي؟
**PDF: نعم.** Download: نعم (للغة والاختبارات). **Print: جزئي** — صفحة `/certificates` (Course Certificates) لديها زر "Print / Download" يفتح نافذة HTML للطباعة وليس PDF فاخر.

### هل يوجد Admin management للشهادات؟
**نعم.** Certificates Studio في `AdminDashboardClient.tsx` تتيح:
- معاينة قالب PDF لكل بوابة.
- إصدار شهادة يدوية باسم محدد + قيم مخصصة.
- لا يوجد resend / revoke / export للشهادات.

### هل يوجد User Dashboard certificates view؟
**نعم.** 3 أماكن:
1. تبويب "شهاداتي" في لوحة الطالب.
2. قسم "مركز الشهادات" داخل التبويب.
3. سجل اللغة + سجل الاختبارات يعرضان أزرار تحميل.

### هل النظام جاهز حاليًا أم جزئي؟
**جزئي — يعمل لكن به نواقص.**
- جاهز: Language, Digital Exams, Admin issuance, Verification.
- ناقص: AI Academy course certs لا تستخدم القالب الفاخر الموحد، Career/Automation/IoT لا يصدرون شهادات تلقائية.

### أهم 5 ملاحظات
1. **خطر Privacy/SEO:** الصفحة القديمة `/certificates/verify/[code]` تسمح بالفهرسة (`robots: { index: true }`) مما قد يفضح أسماء الطلاب على Google.
2. **تجربة Print ضعيفة:** صفحة `/certificates` (Course Certificates) تستخدم HTML بسيط للطباعة بدلاً من القالب الفاخر.
3. **عدم توحيد كامل:** AI Academy course certificates تستخدم نظامًا منفصلاً (`/api/certificates` + `certificates` table) بدون QR أو القالب الفاخر.
4. **لا يوجد Revoke/Resend:** الأدمن لا يستطيع سحب شهادة أو إعادة إرسالها.
5. **Sitemap gap:** صفحات التحقق غائبة تمامًا عن الـ sitemap (صحيح أنها noindex لكنها غائبة حتى من الروابط الداخلية).

### التوصية العامة قبل أي redesign
**لا تعيد تصميم الشكل فقط — بل وحد البيانات أولاً.**
القالب البصري (CertificateTemplate.tsx) جيد فعليًا. المشكلة ليست في الشكل بل في:
- تشتت البيانات على 4 جداول.
- عدم استخدام القالب الفاخر لشهادات AI Academy.
- الصفحة القديمة للتحقق تحتاج إيقاف الفهرسة فورًا.

## 3. Portal-by-Portal Audit

### 3.1 Language Portal

**هل تصدر شهادة؟**
نعم. بعد كل تقييم (حتى الجزئي) يمكن تحميل شهادة PDF.

**من أين تأتي بيانات الشهادة؟**
- `language_results` table (score, level, stages_completed, is_incomplete, certificate_id).
- `profiles` table (full_name).
- `auth.users` (email fallback).

**أين تظهر للمستخدم؟**
- صفحة النتائج: `/language/results?id=...` — زر "تحميل الشهادة".
- لوحة الطالب: تبويب "شهاداتي" — قائمة محاولات اللغة مع زر PDF.
- سجل الاختبارات: `/language/history` — إحصائيات + روابط.

**هل مرتبطة بالنتائج؟**
نعم. الشهادة تُولَّد من صف `language_results` مباشرة.

**هل مرتبطة بالhistory؟**
نعم. `certificate_id` يُخزَّن في `language_results` ويظهر في سجل المحاولات.

**هل يمكن التحقق منها؟**
نعم. عبر `/[locale]/certificates/verify/[certId]` أو `/certificates/verify/[code]`.

**هل يوجد QR؟**
نعم. على PDF. يشير إلى صفحة التحقق الموحدة.

**هل يوجد PDF؟**
نعم. `/api/certificates/language/[id]` تُرجع PDF فاخر.

**هل يوجد certificate ID؟**
نعم. `uuid().toUpperCase().slice(0, 12)` — 12 حرفًا. يُخزَّن في `language_results.certificate_id`.

**ما مكونات الشهادة الموجودة؟**
- CEFR LEVEL + OVERALL SCORE
- اسم الطالب
- نوع الشهادة (Completion أو Partial Completion)
- QR + Certificate ID
- توقيع Ahmed Darhous
- ختم DARHOUS ACADEMY CERTIFIED

**ما الملفات المسؤولة؟**
- `src/app/api/certificates/language/[id]/route.tsx`
- `src/components/language/LanguageResultsClient.tsx`
- `src/components/language/LanguageHistoryClient.tsx`
- `src/lib/certificates/CertificateTemplate.tsx`
- `src/lib/certificates/loadAssets.ts`

**هل تعرض كل البوابات أم بعضها فقط؟**
3 بوابات فقط (AI, Language, Digital Exams). Automation / Career / IoT غائبون.

**هل يوجد mismatch بين dashboard والبوابات؟**

**لا.** `sitemap.ts` لا تُدرج أي صفحة تحقق.

### هل certificate pages نفسها تظهر في sitemap؟
لا. `/certificates` صراحةً مُستبعدة:
```ts
// Excluded from sitemap (noindex or private):
// /certificates, /learning-plans (private user data)
```

### هل verification pages يجب أن تكون index أم noindex؟
- **الصفحة الموحدة** (`/[locale]/certificates/verify/[certId]`): `robots: { index: false }` ✅ صحيح.
- **الصفحة القديمة** (`/certificates/verify/[code]`): `robots: { index: true, follow: true }` ❌ **خطر privacy**.

### هل يوجد canonical؟
لا يوجد canonical tag على صفحات التحقق.

### هل metadata مناسب؟
- الموحدة: `title: "Certificate Verification — Darhous Academy"` ✅
- القديمة: `title: "Certificate Verification | ${code}"` — يعرض كود الشهادة في العنوان ⚠️

### هل هناك خطر privacy من فهرسة أسماء الطلاب؟
**نعم — خطر حقيقي.**
الصفحة القديمة `/certificates/verify/[code]` تُفهرس (`index: true`). Google يمكنه فهرسة:
- Certificate Code
- Holder Name
- Course Title
- Date

هذا يعني أن اسم الطالب وكود شهادته قد يظهران في نتائج Google.

### هل QR URL public بشكل آمن؟
نعم. URL عام وآمن — لا يحتوي على بيانات حساسة.

### هل صفحة verify تعرض بيانات شخصية أكثر من اللازم؟
جزئيًا. تُظهر:
- Holder Name ✅ (ضروري للتحقق)
- Certificate ID ✅ (ضروري)
- Score / Level ✅ (ضروري)
- Date ✅ (ضروري)
لا تُظهر email أو user_id — آمنة نسبيًا.

### هل هناك خطر أن Google يفهرس شهادات شخصية؟
**نعم** — بسبب الصفحة القديمة فقط. الصفحة الموحدة noindex.

### التوصية الواضحة
1. **غيّر `robots` في `/certificates/verify/[code]/page.tsx` فورًا إلى `{ index: false }`.**
2. أضف `canonical` على الصفحة الموحدة.
3. لا تُدرج verify pages في sitemap (صحيح حاليًا).
4. فكّر في إضافة `noarchive` لمنع Google من حفظ نسخة cache.

- **جيد.** أسفل اليسار — مكان قياسي.

### هل التصميم رسمي؟
نعم. الألوان والإطار والختم كلها رسمية.

نعم — مقارنة بمعظم المنصات التعليمية. لكنه ليس "فاخرًا بشكل استثنائي".
