# تنظيم مكتبة البرومبتات

البرومبت المفيد بلا نتيجة أو ملاحظة يصعب إعادة استخدامه. احفظ السياق والنسخ.

## حقول السجل

```text
id:
الاستخدام:
البرومبت:
الأداة والإعدادات:
المرجع وحق استخدامه:
النتيجة المختارة:
ما نجح:
ما يحتاج تعديلًا:
```

## تصنيف عملي

استخدم وسومًا مثل product، education، poster، lighting، background، ثم أضف رقم نسخة.

## خطوات التنظيم

1. أنشئ ID ثابتًا لكل فكرة.
2. احفظ البرومبت والنتيجة معًا.
3. سجل الأداة والإعدادات.
4. أضف وسوم الاستخدام والخصائص.
5. راجع المكتبة واحذف التكرار دوريًا.

## أخطاء شائعة

أسماء «final-final»، وحفظ النص دون الصورة، وخلط مراجع غير مسموحة، وعدم تسجيل التغيير.

## تمرين

أنشئ ثلاثة سجلات لنتائج سابقة. أعط كلًا ID ثابتًا ووسمين وملاحظة واحدة قابلة للتطبيق.

## ما الذي يستحق الحفظ؟

احفظ البرومبت المجرب والنتيجة والأداة والتاريخ والغرض والقيود. افصل "مثالًا ناجحًا" عن "قالب قابل للتعبئة": القالب يكشف متغيرات مثل `[الموضوع]` و`[الخلفية]`، بينما المثال يصف حالة واحدة.

صنف حسب الاستخدام: منتجات، أغلفة، تعليم، شخصيات، وخلفيات. استخدم معرفًا مثل `product-clean-001-v2` وسجل سبب الإصدار. أضف حالة: تجريبي أو معتمد أو مؤرشف، وراجع المكتبة دوريًا لأن استجابة الأدوات قد تتغير.

```text
المعرف:
الاستخدام:
القالب والمدخلات:
الأداة:
مثال النتيجة:
القيود:
درجة الثقة:
المالك وتاريخ المراجعة:
```

لا تحفظ نصًا بلا صورة، ولا تعتمد قالب إنترنت بلا اختبار، ولا تترك بيانات عميل داخله. اختر خمس تجارب قديمة وحوّل اثنتين فقط إلى قوالب. اختبر كل قالب بموضوع جديد؛ إذا فشل فهو مثال خاص لا قالب عام.

## بنية مجلد عملية

أنشئ مجلدًا لكل حالة استخدام، وداخله `approved` و`experiments` و`archive`. لكل قالب ملف نصي أو سجل منظم، وصورة معاينة صغيرة، ونسخة نهائية. استخدم أسماء قابلة للفرز مثل `cover-article-clean-003-v1`، ولا تعتمد أسماء مثل `final-final-2`.

عند إضافة قالب، نفذ اختبار نقل: غيّر الموضوع والجمهور والمقاس. إذا ظل التكوين والضوء مفيدين، فالقالب مرن. إذا نجح فقط مع كوب أبيض على مكتب، سمّه بوضوح كقالب خاص بدل وصفه بأنه عام.

يمكن للفريق إضافة حقل "متى لا تستخدمه"، مثل: لا يناسب المنتجات العاكسة أو الصور التي تحتاج نصًا داخل المشهد. هذا الحقل يمنع تطبيق القالب في المكان الخطأ. عيّن شخصًا للمراجعة، وحدد موعدًا كل ثلاثة أشهر لفحص الروابط والحقوق واستجابة الأداة. احذف البيانات الحساسة قبل المشاركة، وأرشف القوالب التي لم تعد تعمل مع توضيح السبب حتى لا يعيد شخص آخر التجربة نفسها.
