# اختيار أداة Automation

ابدأ بـ Workflow مرسوم. الأداة المناسبة هي التي تنفذه بأمان ويمكن مراقبتها وصيانتها.

لا تبدأ بعدد التطبيقات التي تحمل شعاراتها صفحة المنتج. ارسم الحدث الذي يبدأ العملية، والبيانات الداخلة، والقرارات، والمخرج، والمسؤول عند الفشل. عندها فقط تستطيع معرفة هل تحتاج منصة بسيطة أم منطقًا متقدمًا واستضافة خاصة.

## المعايير

- التكاملات المطلوبة.
- Webhooks والجدولة.
- الشروط والفروع والحلقات.
- معالجة الأخطاء وإعادة المحاولة.
- السجلات والتنبيهات.
- إدارة الأسرار والصلاحيات.
- استضافة سحابية أو ذاتية.
- تكلفة عدد التشغيلات.

اسأل عن طريقة احتساب التشغيل: هل كل خطوة عملية مدفوعة؟ ماذا يحدث عند إعادة المحاولة؟ اختبر أيضًا إدارة الإصدارات، بيئات التجربة، إخفاء الأسرار، وإمكانية إعادة تشغيل خطوة دون تكرار أثر مثل إرسال رسالة مرتين.

## اختبار

```text
Trigger تجريبي
→ تحويل بيانات
→ شرط
→ سجل نجاح/فشل
```

## مثال

شركة تريد نقل طلب نموذج إلى جدول ثم إرسال تأكيد. تحتاج تحققًا من البريد ومنع التكرار وتنبيهًا عند الفشل. أداة سهلة بلا سجل أخطاء قد تنجح في العرض، لكنها لا تكفي عندما يصبح النموذج قناة عمل أساسية. الاختبار الصحيح يتضمن طلبًا ناقصًا وطلبًا مكررًا وانقطاعًا مؤقتًا.

## Workflow اختيار

1. ارسم العملية يدويًا.
2. حدد البيانات الحساسة والأنظمة المتصلة.
3. اختر ثلاثة سيناريوهات: نجاح، بيانات ناقصة، فشل خدمة.
4. نفذ نموذجًا صغيرًا بحسابات اختبار.
5. راجع السجلات والتنبيهات وإعادة المحاولة.
6. احسب التكلفة على حجم شهري مضاعف.
7. وثق إيقاف التدفق والعودة للعمل اليدوي.

```text
الحدث:
الخطوات:
نقطة القرار:
أثر التكرار:
تنبيه الفشل:
البديل اليدوي:
```

## أخطاء شائعة

الاختيار بعدد التكاملات فقط، وتجاهل Debugging، وعدم تقدير حجم التشغيل.

ومن الأخطاء بناء عملية كبيرة دفعة واحدة، وتخزين المفاتيح داخل نص الخطوة، وعدم تعيين مالك للتنبيهات. لا تعتمد Automation لا يمكنك تفسيرها لشخص آخر.

## تمرين

اختبر Workflow من أربع خطوات في أداة مرشحة. سجل كم دقيقة احتجت لاكتشاف خطأ متعمد.

أضف قيمة ناقصة وخطأ اتصال متعمدًا، ثم تحقق من عدم إرسال مخرج خاطئ أو مكرر. وثق أين ظهر الخطأ ومن سيستجيب له.
