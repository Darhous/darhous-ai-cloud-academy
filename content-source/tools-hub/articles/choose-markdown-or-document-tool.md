# Markdown أم مستندات؟

Markdown ممتاز للنص المنظم والملفات القابلة للنقل. محررات المستندات أفضل عند الحاجة إلى تنسيق غني وتعليقات وتعاون مألوف.

القرار ليس منافسة بين صيغتين؛ إنه اختيار لطريقة إنتاج ومراجعة وحفظ المحتوى. قد تكتب التوثيق طويل العمر في Markdown، بينما تستخدم مستندًا تعاونيًا لعقد يحتاج تعليقات وموافقات. ابدأ بدورة حياة الملف ومن سيحرره.

## اسأل

- هل المحتوى طويل العمر؟
- هل يحتاج تعليقات وموافقات؟
- هل يجب حفظه كملفات محلية؟
- ما صيغ التصدير؟
- هل توجد جداول وصور معقدة؟
- من يملك الوصول؟

اختبر نصًا عربيًا حقيقيًا يحتوي عناوين وقائمة وجدولًا وصورة ورابطًا. شاركه مع شخص آخر، اطلب تعليقًا وتعديلًا، ثم صدّره إلى الصيغة المطلوبة. هذا يكشف مشكلات اتجاه النص والخطوط وفقد التنسيق أفضل من مشاهدة الواجهة.

## قرار مصغر

```text
توثيق تقني ونقل سهل → Markdown
تعاون وتعليقات وتنسيق → Document tool
حاجة مختلطة → اختبر التصدير في الاتجاهين
```

## مثال

فريق تقني يكتب دليل تشغيل يتغير كثيرًا ويراجعه المطورون، فاختار Markdown داخل مستودع نسخ لأن التغييرات واضحة والنص قابل للنقل. قسم الموارد البشرية يعد سياسة يراجعها مديرون غير تقنيين، فاختار محرر مستندات بالتعليقات وسجل الموافقة، ثم حفظ PDF معتمدًا في الأرشيف.

## مصفوفة قرار

```text
تعاون لحظي وتعليقات كثيرة: مستند
تاريخ تغييرات ومحتوى نصي منظم: Markdown
تنسيق طباعي معقد: مستند
نشر إلى مواقع متعددة: Markdown غالبًا
جمهور غير تقني: اختبر سهولة التحرير أولًا
```

حدد «مصدر الحقيقة»: الملف الذي يُعد النسخة المعتمدة. إذا استُخدمت الصيغتان، اكتب من يحول بينهما ومتى، ولا تسمح بتحرير نسختين بالتوازي دون آلية دمج.

## أخطاء شائعة

حبس المحتوى في صيغة مغلقة، وخلط النسخ النهائية، وتجاهل العربية واتجاه النص.

وتشمل الأخطاء اختيار Markdown لمجرد البساطة بينما الفريق يحتاج مراجعة مرئية، أو اختيار محرر سحابي بلا تصدير موثوق. لا تهمل الروابط والصور عند النقل؛ نجاح النص وحده لا يكفي.

## تمرين

صدّر مستندًا تجريبيًا إلى PDF وDOCX أو Markdown. افحص العناوين والجداول والعربية قبل الاختيار.

اطلب من زميل إضافة تعليق وتعديل، ثم حدد أين ستعيش النسخة النهائية. سجل أي فقد في التنسيق قبل اعتماد سير العمل.
